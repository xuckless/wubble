# wubble roadmap

A Chromium-based browser with a Slint shell. Web content is rendered off-screen by
Chromium and composited by Slint as GPU textures, so the whole UI (sidebar, tabs,
popups, split views) is one scene we control.

Legend: `[ ]` todo · `[~]` in progress · `[x]` done · **(?)** blocked on an open decision.

## Decided

| Topic | Decision |
|---|---|
| Cosmetic channel and list updates | Cosmetic hiding runs on the helper's context script (`cosmetic.js`, a named channel of `compose`), not on pattern data inside a registered script: adblock's host rules are hashed indexes reachable only per URL, so they cannot be embedded. At V8 context creation every frame sends `hello`; the engine answers on the same channel from `ContentFilter::frame_cosmetic` (CSS rules and procedural filters as JSON, a stylesheet in `adoptedStyleSheets`), runs scriptlets with `run_script_in` (CSP-proof), and answers class/id batches from `ContentFilter::generic_hide`. No `PageEvent`; `page_script` is gone. Limit: one round trip, so a scriptlet can lose a race to an inline head script. "Update now" in Settings is an explicit user action and needs no flag; nothing else fetches lists unless `blocker.lists_auto_update` is on. The four list settings are live: `Applied::BlockerLists` rebuilds the engine off the UI thread and swaps it (newest selection wins) |
| Theme | Dark only, as the design repo decides ("Dark only; light mode comes later"). The tokens are the port's `tokens.slint` verbatim (Palette, Spaces, Radius, Spacing, Chrome, Glass, Fonts, Type, Motion); the light values invented earlier are deleted. Values the port has no token for come from the design repo's CSS (`browser.css`) and live in `app-tokens.slint` (now `ui/kit/derived.slint`; both give way to the generated `ui/kit/gen/` tokens, Decided "Locked widget kit") |
| Slint ids | Slint has only `int` (i32), so `TabItem.id` / `SpaceItem.id` are `int`; the wiring item converts from core `u64`/`u32` with `try_from`, never truncating silently |
| Reduced motion | One flag with one writer (`host/look.rs`): `motion::reduced` (thread-local, read inside `step`, `Stretch::update` and `squash_at`, so every spring snaps with no per-caller change) and Slint `Calm.reduced` (the `Motion` shift, scale-from and press go to rest: entrances fade only). Its inputs: the setting `ui.reduce_motion`, and on auto the OS preference behind one `MotionSource` trait (`os_motion.rs`) |
| Glance | A peek is a tab placed like a background tab after its opener but held in `Model.glances` (one per window): on screen (last in `window_tabs`, so Active), never a sidebar row, never saved (`Model::for_session`), closed when its opener leaves the screen, promoted by `PromoteGlance`. Shift+click is a page's new-window request with a gesture (`popup::Outcome::Glance`) |
| Folder rows | A folder header is a row of the one tab list (negative id `-2 - folder`, `shell::folder_row_id`) on the same springs and pitch; the driver maps Slint ids injectively (`id as u32`) |
| Auto-archive, routing, tidy, never sleep | The Archive list lives in the store (like recently closed: SQL search and paging), the model keeps only `Tab::last_active_ms` (unix ms, stamped on hide, 0 = unknown until the first tick) and `Command::Tick { wall_ms }`; `archive::due` is pure. A tab closes only after the store confirmed its row. Routing rules and never-sleep sites are List settings; `routing::host_in` is the one host matcher. `Keep { Normal, Awake }` is derived by the model, never set by hand. The preview card has no bucket widget (the design has no tooltip), so it is written on `GlassPanel` with the owner's UR tooltip numbers |
| Key routing | Each default binding has a `Route` column: `Shell` (shell always takes it: NewTab, CloseTab, ReopenClosedTab, NewWindow, Next/PrevTab, Quit, Fullscreen, spaces, sidebar; the Chromium `kReservedCommandIds` / Firefox `reserved` set plus wubble-only actions) or `PageFirst` (page gets the key, the shell acts only if unhandled, via CEF `OnKeyEvent`; everything else, incl. Zen's Mod+Alt+S compact mode). Overrides take the action's default route. In page fullscreen only Fullscreen stays `Shell` |
| Licence | GPL-3.0-only (matches Slint's GPL option; Chromium/CEF are BSD and compatible) |
| Platforms | Daily-drive targets: Linux (lead, Wayland) and macOS, both built locally. Windows is built and tested on CI runners only and may trail by a milestone |
| Engine, phase 1 | Prebuilt CEF 156 via the `cef` crate (stock Chromium, **not** ungoogled) |

| Glass under load | Glass degrades before animation drops a frame. One enum `scene::Quality` `Full/HalfRes/Cached/Flat`, moved by a pure `Governor::next(cost, budget)`: each level's load is smoothed (mean, then a 1/16 EWMA, each frame capped at 2 budgets) and remembered after leaving it; it steps down when, after 32 frames, the level's load is over 0.9 budget, and up when, after a 360-frame hold, the load is under 0.6 budget and the level above last measured under 0.8 budget or a back-off of `360 << n` frames has run out, `n` growing by one (cap 6) each time a step up is followed by a step down within 4 holds and reset when a step up holds that long. A GPU that cannot afford a level settles below it; a hitch changes nothing; a transient overload costs one round trip (2026-11-18, after the governor cycled through every level on a 300 Hz display). Each level is a knob of the design scene: `HalfRes` halves the composite and blur pyramid and the Jacobi iterations; `Cached` also moves the backdrop only every 8th frame (by the time of all eight, so the liquid keeps its speed); `Flat` freezes the backdrop and draws the glass as a flat tint (one fill colour per panel, rim, sheen ring and beam; no refraction, dispersion, press waves, specular or pointer light) |

| Glass fallback | Chosen once at startup into `backdrop::Glass { Scene, SlintOnly }` and logged (`wubble: glass: scene` / `slint-only (reason)`): `Renderer::try_new` builds the pipelines inside a wgpu validation error scope, so a device that refuses them gives `Err` instead of a panic; `WUBBLE_GLASS=slint` or the `glass.scene` setting off forces the fallback. ## Layout

```
crates/wubble          main binary: wires engine + gfx + ui
crates/wubble-helper   CEF subprocess entry point (renderer/GPU/utility), no Slint
crates/wubble-core     tabs, spaces, sleep policy, session — pure logic, unit-tested
crates/wubble-engine   the only crate that names CEF types
crates/wubble-gfx      the only crate that touches native texture handles
crates/wubble-ui       Slint shell
crates/wubble-sysmem   OS readers: memory pressure, process memory and CPU
crates/wubble-ax       a page's accessibility tree (CEF values) mapped to AccessKit, pure
ux/                    UX pack (source of truth for wubble-ui)
docs/adr/              one short record per architectural decision
```

Rule: the shell never sees a CEF type. That boundary is what makes the M6 engine swap cheap.

Working rules and code principles: see [AGENTS.md](AGENTS.md).

## Risks

1. **Slint ↔ wgpu texture import is an `unstable-` feature.** It can change on any Slint minor. Pin versions; M0 decides if it holds up.
2. **Own-drawn glass and the living backdrop must fit the frame.** The scene runs about 40 small render passes per frame (fluid step, composite, blur pyramid, glass) at 120 Hz alongside Chromium's own GPU work, within 8.33 ms. Measured by hand; the quality ladder is the fallback.
8. **Windows is CI-only.** Input, IME and windowing bugs there will be found late.
3. **Prebuilt CEF is not ungoogled and has no proprietary codecs.** Until M6, wubble talks to Google services like stock Chromium and H.264/AAC video may not play.
4. **`welding` pins CEF** (upstream 0.15 → CEF 154). Forked into `vendor/welding`, which already bumps `cef` to 156.6 itself; each CEF upgrade is ours to do: re-apply `WUBBLE_CHANGES.md` on a newer welding, or bump `cef` in the fork.
5. **Extensions under windowless CEF are partial**, hence deferred to M6 — where it is a real Chromium patching project, not an integration task.
6. **OSR costs one extra composite per frame** and bypasses direct scanout for video. Measure in M0; a native-subsurface fast path for fullscreen video is the escape hatch.
9. **Turso is pre-release (0.9.0-pre).** History and passwords will sit on a pre-1.0 database; keep the file format SQLite-compatible and back up before migrations.
7. **Maintenance load**: an ungoogled+CEF patch queue rebased for every Chromium milestone is permanent work for one person.
