## Read aloud with the OS voice (page, selection, Reader view) (`read-aloud-os-voice`)

Key: `read-aloud-os-voice` · engine patch: no · state: not written.

Chrome's Reading mode has Read aloud: play/pause, speed, voice choice, and word or sentence highlighting, with OS or network voices. Its context menu also reads selections aloud (ChromeOS select-to-speak). wubble has none (docs/research/tts.md is shelved; TODO "Read aloud with an on-device voice"). Build the OS-voice road from tts.md "If picked up": (1) Core: `wubble_core::read_aloud` gets one enum (Idle, Preparing, Speaking{sentence}, Paused{sentence}, Done) with a pure transition, plus sentence segmentation of the Reader's extracted text (Unicode sentence boundaries via `unicode-segmentation`, MIT/Apache). Speaking is refused while a screen reader runs (`screen_reader.rs`) unless the user asked explicitly. Tests. (2) A `Voice` trait in a new crate `wubble-voice` (OS APIs only, no CEF): `voices()`, `speak(text, voice, rate) -> utterance id`, `pause`, `resume`, `stop`, with word-boundary and end events. Implementations: Linux speech-dispatcher (the `speech-dispatcher` crate or `ssip-client-async`, licence checked), macOS `AVSpeechSynthesizer` (objc2-avf-audio) and Windows SAPI/`Windows.Media.SpeechSynthesis` (compile-checked by CI). (3) Text source: the Reader document (`wubble_core::reader`, `assets/reader.js`) returns sentences with DOM ranges, and highlighting is a CSS Highlight API (`::highlight`) set per sentence or word by `View::eval`. Without reader mode, use the selection or the Readability extraction run without replacing the page. (4) UI: `Action::ReadAloud` with a palette entry, a context-menu row "Read aloud" for a selection, and a kit mini player (play/pause, speed, voice select) in the Reader toolbar. Settings: voice and rate.

## Read aloud: bundled or opt-in on-device neural voice (`read-aloud-model-voice`)

Key: `read-aloud-model-voice` · engine patch: no · state: not written.

Where the OS has no voice (most Linux installs without speech-dispatcher), Chrome falls back to its network voices. wubble must make no request by default, so docs/research/tts.md proposes a small on-device model as a second `Voice` implementation: tiny-voca (Apache-2.0, about 15-27 MB, English only), compared with Piper (its eSpeak NG phonemizer is GPL-3.0-or-later, acceptable), Kokoro and KittenTTS. To build, on top of read-aloud-os-voice: (1) Pick one after reading the licences tts.md left unchecked (`dizione`, CMUdict, homograph data). Record the pick in the report. (2) Implement `Voice` in `wubble-voice` as `ModelVoice`. Inference runs through `ort` (shared with ocr-backends' ORT dependency) in a child process, with sentence-by-sentence synthesis to 24 kHz PCM. Playback through `cpal` (Apache/MIT), with word timing estimated from phoneme durations for highlighting. (3) Delivery: unless the model is small enough to ship (decide by size), download it only on a press, behind a Bool `read_aloud.model_download` (default 0), through `wubble-engine/src/fetch.rs`, with a pinned SHA-256. Use a pure state machine for the download (Absent, Downloading, Ready, Failed) in `wubble_core::read_aloud`, with tests. (4) The voice list in the read-aloud player marks model voices and the languages they cover. The OS voice is preferred when it exists.

## Reader mode: Chrome's reading-mode controls in a toolbar (`reader-toolbar-options`)

Key: `reader-toolbar-options` · engine patch: no · state: not written.

Chrome's reading mode has a toolbar with font (several faces), font size, line spacing (standard, loose, very loose), letter spacing (standard, wide, very wide), colour theme (default, light, dark, yellow, blue), links on/off and images on/off, plus Read aloud. Changes apply live, and it also follows a selection in the page. wubble's reader (`wubble_core::reader`, `ReaderPrefs`: size, width {narrow, medium, wide}, font {serif, sans}, theme {dark, light, sepia}; `assets/reader.js` with fixed line-height 1.65 and letter spacing) is set only from Settings rows (`READER_SIZE`, `READER_WIDTH`, `READER_FONT`, `READER_THEME` in `settings.rs`), with no in-page controls. To build: (1) Core: `ReaderPrefs` gains `line_spacing` (3 steps), `letter_spacing` (3 steps), `links: bool` and `images: bool`, and the themes gain yellow and blue, all with word tables like `WIDTH_WORDS` and new Settings defs. `css_vars` emits `--wb-line`, `--wb-letter` and the theme colours from generated kit tokens where they exist. Update the tests. (2) `reader.js` reads the new vars, and links off renders anchors as plain text and images off hides `figure`/`img`. (3) A toolbar: while reader is `On`, the address pill's reader glyph opens a kit popover (segmented controls for spacing, a slider for size, swatches for theme, toggles for links and images; reuse `controls::segmented`, `slider`, `swatches`, `toggle`). Each change writes the setting and re-applies `css_vars` through `View::eval` without a reload. Also show an estimated reading time under the title (words / 238 wpm, computed in core). (4) The Read aloud button joins this popover once read-aloud-os-voice lands.

## Task manager: Chrome's columns, sorting and row actions (`tm-columns`)

Key: `tm-columns` · engine patch: no · state: not written.

Chrome's task manager shows Memory footprint, CPU, Network and Process ID by default. Optional columns (right-click the header) include GPU memory, JavaScript memory, image, script and CSS cache, SQLite, idle wake-ups, priority and keepalive count. Columns sort on click, a double-click on a row focuses its tab, and End process works on a multi-selection. wubble's page (`wubble_core::tasks`, `host/tasks.rs`, `TaskItem` in wubble-ui) shows title, state, RSS, CPU and busy reasons. It has no Network or JS memory column, no sort, no row activation and no multi-select. To build: (1) Network: per-tab bytes per second from the received byte counts that wubble's request path already sees. Use `CefResourceRequestHandler::OnResourceLoadComplete` `received_content_length` in the engine's request handler (`wubble-engine/src/filter.rs`), summed per view into a counter the meter reads each second. A pure rate calculation goes in `tasks.rs`. (2) JS memory: while the page is shown, `Runtime.getHeapUsage` per live tab over `View::cdp` once per sample, as "used (total)". (3) GPU memory for the GPU process: `SystemInfo.getInfo` is too heavy, so leave it out unless tm-renderer-pids' table provides it. (4) Sort: a pure `tasks::sort(rows, column, dir)` that keeps a tab's rows grouped as Chrome does, with tests. The column and direction live in host state. (5) Column picker: a kit menu on the header, with choices stored as a hidden List setting. (6) Double-click or Enter on a tab row activates that tab (`Command::Activate`). (7) Multi-select with Shift/Ctrl and End for all. All UI from kit components (list rows, menu, header) in `crates/wubble-ui/ui`.
