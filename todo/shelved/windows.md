## Windows taskbar and window integration: AppUserModelID, jump list, snap layouts (`windows-shell-integration`)

Key: `windows-shell-integration` · engine patch: no · state: not written.

Chrome on Windows sets an explicit AppUserModelID, so its windows group under the pinned icon and toasts carry its name. Its jump list has Tasks (New window) and recently closed or most visited pages. Hovering its maximize button opens Windows 11 snap layouts. wubble has none of this: the window is frameless on Windows (`wubble-ui/src/window.rs` `NATIVE_FRAME` is macOS only), the shell draws its own buttons, and nothing names an AUMID. To build, in `crates/wubble/src/` behind `#[cfg(windows)]`, one module (`win_shell.rs`): (1) `SetCurrentProcessExplicitAppUserModelID("wubble.Browser")` in `main` before any window, the same id the installer's shortcut carries (MSI feature); (2) a jump list via `ICustomDestinationList` with a Tasks category ("New window", run as `wubble --new-window`, the switches feature) and a "Recently closed" category from `wubble_core::closed`, rebuilt when that list changes, not per frame. The data is a pure fn in core (`jumplist(&Closed) -> Vec<Item>`) with unit tests; (3) snap layouts: subclass the HWND (`SetWindowSubclass`) and answer `WM_NCHITTEST` with `HTMAXBUTTON` over the shell's maximize button rect. The rect comes from the Slint window-frame component (`ui/components/window-frame.slint`) through a property the host reads, the same way the edge resize zones reach `window.rs`. Nothing is drawn outside the kit.

## Windows: precision touchpad pinch-zoom and history swipe (`win-touchpad-gestures`)

Key: `win-touchpad-gestures` · engine patch: no · state: not written.

Chrome on Windows uses DirectManipulation for precision touchpads. A pinch zooms the visual viewport smoothly (not page-zoom steps), and a two-finger horizontal overscroll navigates back or forward with the arrow bubble. In wubble on Windows, winit has no `PinchGesture`, and a precision touchpad pinch arrives as Ctrl+wheel. `zoom.js` and the engine pinch code treat it as a page-zoom step (`Action::ZoomIn/Out`) or a Touch-road pinch per wheel, and no history swipe is reported (host/gesture.rs). To build: in the Windows `Aux` worker (crates/wubble/src/wl/windows.rs, shared with win-ole-dnd; one owner), create a DirectManipulation manager and viewport per HWND as Chromium's `ui/base/win/direct_manipulation` / `content/browser/renderer_host/direct_manipulation_helper_win.cc` does (BSD-3, notice entry). Feed pointer hit-test contacts (`DM_POINTERHITTEST`) into it, and map viewport transform updates to `AuxEvent::Pinch(PinchInput)` (scale) and to `AuxEvent::Swipe` (horizontal pan with the page not consuming it), with the end on the ready state. Ctrl+wheel from a real mouse keeps the page-zoom step. A pure translation from DM transform deltas to gesture inputs goes in wubble-core with tests. Use the `windows` crate (MIT/Apache).
