# Deviations: what the web does that Slint cannot (for the owner)

Status (2026-11-19): current list of places where the web does something Slint cannot, with the fallback each uses; for the owner.

Each row: control, what the web does, what Slint can do, evidence, the fallback.

## Controls kit A (lane L3 press, ui2b/press)

| Control | web | Slint | evidence | fallback |
|---|---|---|---|---|

| Button glass, Toggle body, Confirm | `backdrop-filter: blur(24px) saturate(170%) brightness(1.08)` (`.wb-thin`) | the kit GlassPanel's fallback (fill, rims, top light, shadow) unless the scene glass is under it | kit-plan section 6, L2-2 | GlassPanel `over-wgpu: false` (the standard fallback) |

## Chrome (lane L4, ui3/chrome)

- Held split line fade (`.wb-split-line`: opacity 0 -> 1 over .2 s ease-out, back over .15 s ease-in): wubble's seam path is "" as soon as the string is straight, so the fade-out has nothing to draw; the line shows at full opacity while bowed. Fallback until the host keeps the last path for 150 ms (host glue).
- New-tab command origin (`chrome.tsx:291` `r.left + 20`): still left + 40 (`Shell.command-origin-dx`); the TSX number is not extracted by `tools/fidelity/extract.mjs` (it reads CSS and tokens only), and the lane rule forbids typing it. Needs an extractor row for TSX open origins.
- Generator: `BrowserCss.wb-split-line--opacity` is typed `length 0px` (`opacity: 0` read as a length); not used.

## Chrome, second half (lane L4, ui5/chrome)

- Split seam line: resolved. `SeamStrip { kind: split }` draws no rest string and only `.wb-split-line` (sky 1.6), straight while held with no bow, else the bowed string; its opacity takes the destination rule (in .2 s ease-out, out .15 s ease-in) and the line keeps drawing while it fades out. The web clears the line's `d` the moment the seam is released (chrome.tsx:146), so its .15 s fade-out is never seen there; wubble shows the CSS rule's fade (the transition the CSS states). The pill follows `x + bend, gy` (host `SeamView`).
- Generator: opacity declarations are numbers now (`lib/values.mjs` `case 'opacity'`); 31 tokens retyped from `0px` to `0`, none used as a length.
- Address text weight: the pill's host reads heavier than the web's at the same role (mono 13 / 400, `AddressText.role` from `Role.wb-mono` + `Role.wb-address-text`); the same font at the same weight, so it is the mono face's rendering under Skia (variable font axis or hinting), not the pill. Evidence: `ui5-chrome/address/01-sidebar-extended.png` vs `baseline/web/1x/sidebar-extended.png`, crop 10,52-260,96. For the fonts lane.
- Favourite tile shadow (`useGlass(..., { shadow: .3 })`) and the address pill's shadow 0: the scene draws one surface shadow for every glass (B-035, `wubble-gfx` `state.rs`), so wubble's tiles show no distinct .3 shadow. Scene lane. Evidence: `ui5-chrome/favs/01-sidebar-extended.png` vs the web crop 0,95-268,180.
- Computed style vs the rule alone (affects every lane): the generator reads each CSS rule alone, but `.wb button { font: inherit; color: inherit }` (wubble.css:12, specificity 0,1,1) outranks every single-class rule on a `<button>` (0,1,0). The web therefore renders the Space glyphs ink (not `.wb-space` haze; measured 242,244,250 in `baseline/web/1x/sidebar-extended.png` at 58..120,772..796), the New tab row ink at 14 px (not `.wb-newtab` mist 13.5), `.wb-ib` ink at rest (the controls lane already follows this), and the window lights' glyphs visible at rest (`.wb-light` transparent loses too; first-half kit `window-lights.slint` still follows the rule alone: left for review, the owner's eye decides). This lane follows the computed style for the Space switcher and the New tab row (the spec's "glyph haze at rest" is the rule alone; the web never shows it). A cascade-aware generator would make this mechanical.
- Peek (the store's peek slot, `wubble_core::overlay::Kind::Peek`): entering the edge strip (`.wb-peek-edge`) shows the peek at once, as the design (wubble used to wait 60 ms); the 60 ms timer is the design's `onMove` path, which wubble hears as the window's west resize strip (it lies over the edge's first pixels). One deliberate difference: the design never cancels `leaveSide`'s 260 ms timer, so a pointer that leaves the peek and comes back within 260 ms loses it under the pointer; wubble's slot cancels it on return (`Leaving` + `Keep` -> `Shown`). The peek goes at once when it ends (the design drops `.wb-side-peek`; only the entrance is animated). Shot: `ui5-chrome/sidebar/overlay/05-peek-over-page.png`.
- Command bar: a pick closes the bar at once, as the design (`go` sets `d.command = null`, no exit); only Escape, the scrim and the keys leaving run `wb-pop-out`. The pop-in's fade and blur end at 60 % of the run (`wb-pop-in` 60 % step, now generated as `wb-pop-in-k-60pct--at`) on the run's ease-out over that span; CSS eases each keyframe segment, Slint eases the property's own tween: the same curve over the same span. The blur of the pop (5 px in, 4 px out) is not drawn: the panel is scene glass whose own opacity carries the fade (a backdrop-blur child would blur the scene glass under it); gap for the scene lane.
- Command bar text weights (labels 14, the input 17) read heavier than the web's at the same role, as the address text (font rendering, not the bar). Evidence `ui5-chrome/command/07-command-bar.png` vs `baseline/web/1x/command-bar.png` crop 330,40-1260,560.
- Settings Select list: the panel is drawn in the page by Slint (`Shell.thick-unblurred-fill`, no blur), not by the scene: the scene's window-level glass image (`GlassOver.top`) lies over the whole page, rows of a list that sits in the page included, so the list showed as an empty glass box. A window-level list (the context menus') keeps the scene's glass. Road to the design's blur: draw the page's lists in a window-level layer (a design decision).
- Generator additions (all additive): keyframe steps' place (`<name>-k-<n>pct--at`), `min(Npx, calc(100% - Mpx))` widths (`--width-max`, `--width-inset`), `translateX(calc(-100% - Npx))` (`-pct` and the length), and TSX values `Tsx.cmd-row-lead` (60 ms), `cmd-rows` (7), `cmd-head-icon` (18), `address-origin-dx` (40), `new-tab-origin-dx` (20: resolves the first half's "new-tab origin still left + 40").
