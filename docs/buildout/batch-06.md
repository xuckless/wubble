## `web-notifications`: Web notifications shown by wubble, with click-to-tab

Area: web-platform-ui. Needs an engine patch: no.

In Chrome, once a site is allowed, new Notification() and registration.showNotification() show OS notifications. A click focuses the window, selects the tab and fires the click event. wubble grants the Notifications permission (prompt.rs), but display depends on Chromium's NotificationPlatformBridge inside CEF: on macOS it needs Chrome's alerts helper app, which is not in the bundle. Clicks call WebContentsDelegate::ActivateContents, which Alloy leaves empty, so the tab is never brought forward.
Build repo-side: (1) Add a main-world content script channel `notify` to wubble-helper/src (registered in main.rs `compose`). For a granted origin it replaces window.Notification and ServiceWorkerRegistration.prototype.showNotification from page contexts with a shim. The shim keeps the API shape (permission, requestPermission → the real one, onclick/onclose/onshow, close(), tag replacement, silent, requireInteraction) and posts {id, title, body, icon, tag} to the browser. (2) On the browser side, show the notification in crates/wubble through the `notify-rust` crate (MIT/Apache-2.0; DBus org.freedesktop.Notifications on Linux, the native centre on macOS, toast on Windows), with a THIRD_PARTY_NOTICES entry. On click, raise the window, select the tab and send `click id` back to the shim, which dispatches onclick. Close and replace work the same way. (3) A click on a registration notification focuses the tab and calls the page's notificationclick-equivalent listener only when the page registered one through the shim. Worker-initiated notifications stay Chromium's (push needs FCM, which stays off). (4) Add a Settings row "Show notifications from sites". Icons are fetched only for already-loaded page resources.

## `pw-os-reauth`: OS re-authentication before revealing, copying, exporting or editing secrets

Area: passwords-autofill-sync. Needs an engine patch: no.

Chrome on macOS and Windows asks for the device password, Touch ID or Windows Hello before showing, copying, editing or exporting a saved password (and before filling a saved card), with a grace period of about a minute; Linux Chrome has no prompt. wubble unlocks the vault through the keyring only (`VaultCommand::Unlock`, crates/wubble-vault/src/command.rs), and Reveal/Copy run without a check (crates/wubble/src/host/pages.rs `Then::Show`, `Then::Copy`). Build: a `trait Reauth { fn ask(reason: &str) -> Result<bool, String> }` in crates/wubble (one shared trait, per-platform impls): macOS `LAContext evaluatePolicy:deviceOwnerAuthentication` via objc2-local-authentication; Windows `UserConsentVerifier::RequestVerificationAsync` (windows crate), falling back to `CredUIPromptForWindowsCredentialsW`; Linux: a no-op that returns true, as Chrome does, with an optional polkit check left out. A pure gate in wubble-core, `reauth::Gate` (one enum: `Fresh{until}`/`Stale`, `fn transition`), decides whether an action needs a prompt (60 s grace, reset on lock and when the page is left). Route Reveal, Copy, Edit (when the password field changes), ExportCsv and card fill through it in crates/wubble/src/host/pages.rs, running the prompt off the UI thread. Setting `passwords.reauth` (crates/wubble-core/src/settings.rs, Section::Privacy, default true on macOS and Windows, hidden on Linux). Unit tests for the gate.

The answer comes through a new table function `permission_answered(request_id, allow)`, which runs the prompt's done callback (`ExtensionInstallPrompt::DoneCallback` with `Result::ACCEPTED`/`USER_CANCELED`). Bump the table to `cef_wubble_ext_v2` with a `size` check, so a v1 engine keeps working. wubble side: `crates/wubble-engine/src/ext_api.rs` adds `ExtRequest::PermissionPrompt { id, extension, kind, permissions }` and `Engine::answer_permission`. ## `macos-open-urls`: macOS: open links and files from other apps, Dock reopen and Dock menu

Area: platform. Needs an engine patch: no.

On macOS, LaunchServices delivers a clicked link or an "Open With" file as an Apple Event, not as argv. wubble handles neither. `crates/wubble-engine/src/mac_app.rs` overrides only `sendEvent:` and `terminate:`, and `wubble-bundle`'s Info.plist (`crates/wubble-bundle/src/main.rs` `add_plist_keys`) has no `CFBundleURLTypes` or `CFBundleDocumentTypes`, so wubble cannot even be picked as the default browser. To build: (1) in `add_plist_keys`, `CFBundleURLTypes` for http and https (role Viewer) and `CFBundleDocumentTypes` for public.html, public.xhtml, com.adobe.pdf, public.svg-image, public.png/jpeg/gif/webp and public.plain-text, with `LSHandlerRank` Alternate. Chrome's Info.plist is the model. (2) In `mac_app.rs`, from `prepare_process` before `finishLaunching`, register `NSAppleEventManager setEventHandler:` for kInternetEventClass/kAEGetURL ('GURL'). Add `application:openURLs:` (files, `file://`) to winit's application delegate class with `class_addMethod`, as `wl/macos.rs` does for winit's view. (3) Each URL goes to the host as `instance::Message::Open` (the same path a second start takes, `instance::listen`'s `deliver`), queued until the first window's host exists, because a cold start's event comes before it. (4) `applicationShouldHandleReopen:hasVisibleWindows:`: with no visible window, open a main window (Chrome's behaviour). (5) `applicationDockMenu:` with "New Window". The menu is built from the action table, so it runs `Action::NewWindow` through `perform.rs`. Compile-check from Linux only. Run nothing on the Mac.

## `ambience-damage-reach`: Page damage rebuilds the page blur only within the ambience's reach

Area: todo-b. Needs an engine patch: no.

Damage far from any glass, such as a spinner in the middle of the page, still marks P (the page-inclusive blur pyramid) stale. The ambience then rebuilds at 8 Hz, each time as a whole-window frame. This item also covers the TODO item that a page frame should touch the scene and pyramid only while overlay glass or motion is on screen.

To build: in crates/wubble-gfx/src/scene/pages.rs, add an `AMBIENCE_REACH` (about 130 logical px from a pane edge, from the ambience's blur radius) and a pure `fn reaches(damage: Rect, page: &PageRect, overlays: &[Rect]) -> bool`. It is true when the damage lies within the reach band of the pane's edge, or under an overlay-glass rect. Change `Renderer::pages_written` and `set_pages` in scene/render.rs to take the frame's damage: the in-place `Damage` from `FramePresenter::present_damaged` (crates/wubble-gfx/src/import.rs), where a whole frame counts as reaching. Set `pages_stale` only when it reaches. Pass that damage from crates/wubble/src/host/panes.rs (around line 839, next to `mark_rect`) through `Glass::pages_written` in backdrop.rs. In `page_blur`, a stale page with only the ambience on and no overlay keeps its low rate. With no overlay glass over a pane and the ambience at 0, the host skips `set_pages`/`schedule_pages` for page frames altogether. Unit tests in pages.rs. All platforms.

## `save-page-complete`: Save page as: Webpage, Complete (HTML plus resources folder)

Area: page-interaction. Needs an engine patch: no.

Chrome's "Webpage, Complete" (`content/browser/download/save_package.cc`, BSD-3) serializes the live DOM of every frame (`WebFrameSerializer`). It saves each subresource (images, stylesheets, scripts, frames) into `<name>_files/` and rewrites the references to relative paths. It adds the `<!-- saved from url=(NNNN)... -->` mark-of-the-web comment and reports progress in Downloads. wubble has nothing like it. To build, after save-page-formats provides the chooser and `Action::SavePage`: use CDP through crates/wubble-engine/src/cdp.rs. `Page.getResourceTree` and `Page.getResourceContent` give each resource's bytes from cache, with no new network request. `DOM.getDocument` with pierce and `DOM.getOuterHTML` (or a helper script serializer) gives each frame's current DOM. A pure `wubble_core::savepage::complete` module plans the files from (frame HTML, resource URLs and MIME types): unique safe file names as Chromium's `SavePackage::GetSavableFileName` makes them, a rewrite map for src/href/srcset/url() in inline style and in saved CSS, and the mark-of-the-web line. It is unit-tested on fixture strings. The host writes the files on a worker thread under the chosen folder and reports a downloads-list entry with progress and errors. Resources not in cache are left as absolute URLs (no fetch), and that is documented in decisions.
