## `web-share`: navigator.share: a share sheet

Area: web-platform-ui. Needs an engine patch: no.

In Chrome on macOS and Windows, navigator.share({title, text, url, files}) opens the OS share sheet. Chromium on Linux has no navigator.share. In wubble's windowless CEF the macOS share picker has no anchor window, and the Linux API is missing.
Build: (1) Add a main-world content-script channel `share` (wubble-helper/src, main.rs `compose`). It defines or replaces navigator.share and navigator.canShare with spec behaviour: a transient user activation is required (navigator.userActivation.isActive), validate the data, reject with AbortError on cancel, NotAllowedError without activation, and InvalidStateError while one is open. It posts the request to the browser. (2) Add a pure machine in crates/wubble (one enum and a transition, like surface.rs Dialog) that answers each share exactly once and closes on navigation or tab close. (3) On macOS, show NSSharingServicePicker anchored at the window's content view (objc2, as crates/wubble already uses for macOS). On Linux and Windows, show a kit popover (overlay/a/a-popover.slint + a-menu-list.slint) with "Copy link" (the clipboard path in crates/wubble/src/clipboard.rs), "Email" (a mailto: built from title, text and url, handed out through wubble_core::external) and "Save files" for shared files. The popover is a derived piece on the owner's sheet. (4) Files arrive as blobs through the channel, up to a size cap; larger ones are refused with DataError.

Area: passwords-autofill-sync. Needs an engine patch: no.

Chrome fills credit card forms (cardholder name, number, expiry month/year or combined, optionally CVC) from saved cards, offers to save a card after a submit, masks numbers as "Visa ....1234", requires OS re-auth before filling on macOS/Windows, and manages cards under Settings > Autofill > Payment methods. Save-after-submit prompt for a new valid card. `InternalPage::PaymentMethods` page and `autofill.cards` setting (default on) in the Autofill section. No card data in agent sessions.

Area: devtools-extensions-internals. Needs an engine patch: yes.

In Chrome, `chrome.tabs.getCurrent()` returns undefined in an action popup, and `chrome.extension.getViews({type:'tab'})` does not count the popup. In wubble, the popup and the DevTools panel are windowless views that carry a `SessionTabHelper` id. Patch `53-src-non-tab-views.patch`: in `chrome/browser/extensions/api/tabs/tabs_api.cc` `TabsGetCurrentFunction::Run`, and in `extensions/browser/extension_function...`/`chrome/browser/extensions/api/runtime` `GetViews` (`ExtensionHost`/`ProcessManager` view type), consult the registry from `10-cef-tabs-windows.patch` (`cef_wubble_ext` window and tab state). A web contents whose browser id is not in the last `set_state` tab list answers `getCurrent` with no tab, and `getViews` reports `mojom::ViewType::kExtensionPopup` for views wubble marks as popups. Add a table function `mark_view(browser_id, kind)` (popup, devtools, side panel), called by wubble when it opens such a view: `host/ext_ui.rs::open_popup` and `host/devtools.rs::open_panel`. wubble side: wrap it in `crates/wubble-engine/src/ext_api.rs` (`Engine::mark_ext_view(ViewId, ExtViewKind)`), guarded by a table version check, so an older engine just skips it. Acceptance: Bitwarden's popup lays out at its own 380 px.

## `instance-handoff`: Second start: many URLs, local files, the working directory and the activation token

Area: platform. Needs an engine patch: no.

Chrome opens every URL or file on its command line, resolves relative paths against the caller's working directory, and the running instance's window comes forward, even on Wayland. wubble's CLI takes one optional `page` (`crates/wubble/src/cli.rs`). `instance::Message` carries `Open(String)` or `Focus` (`crates/wubble/src/instance.rs`), the desktop entry's `%U` can pass several URLs, a relative `wubble page.html` is never turned into a `file://` URL, and `host.rs`:887 calls `focus_window()`, which Wayland compositors refuse without a fresh activation token. To build: (1) cli.rs: `page: Vec<String>`. Each argument that names an existing path (relative to the cwd, or absolute) becomes a `file://` URL (`url::Url::from_file_path`), and anything else goes through the omnibox rule as today. Put that in a pure `wubble_core` fn with tests. (2) A wire format v2 in `instance.rs`: `open <url>` lines repeated, then `token <xdg-activation token or DESKTOP_STARTUP_ID>`, then `end`, under `MAX_MESSAGE`. `parse_message` stays strict, an old single line is still accepted, and tests cover both. (3) The primary opens the first URL as today (a Little window) and the rest as tabs in it, or as new tabs in the last focused main window if that is the policy, matching Chrome's "new tab in the last window". (4) Activation: read `XDG_ACTIVATION_TOKEN`/`DESKTOP_STARTUP_ID` in the second start. On Wayland the worker (`wl/wayland.rs`, on the windows' connection) binds `xdg_activation_v1` and calls `activate(token, surface)`. On X11 send `_NET_ACTIVE_WINDOW` with the startup id's timestamp. On macOS and Windows call `NSApp activate` / `AllowSetForegroundWindow` from the second process.
