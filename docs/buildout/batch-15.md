## `live-caption-local`: Live captions from on-device speech recognition

Area: media-downloads. Needs an engine patch: no.

Chrome's Live Caption captions any audio a tab plays. It uses Google's closed SODA library, downloaded by the component updater, and a renderer-side audio tap in //chrome. Both are out of reach: SODA is proprietary and needs a download from Google, and its tap is not in windowless CEF. A wubble version can still be built from parts in reach. CEF's CefAudioHandler delivers a browser's PCM, but while capture runs it silences the page's own output (crates/wubble-engine/src/media.rs notes this). So wubble must play the captured audio itself.

What to build: (1) welding: wrap CefAudioHandler (OnAudioStreamStarted, OnAudioStreamPacket, OnAudioStreamStopped) behind a `wubble change`, queuing f32 planar packets per view. (2) Engine and host: while captions are on for a tab, start capture on it and play the PCM through a small output, the cpal crate (Apache-2.0). Keep A/V offset as low as the buffer allows, and say in the setting's text that sync may drift. (3) Recognition: whisper.cpp through whisper-rs (MIT/Unlicense) on a worker thread, fed 16 kHz mono chunks. The model is an opt-in download (`media.captions_model_download`, default off) or a file the user picks; nothing ships. (4) Core: a pure caption buffer in wubble-core (segments in, lines out, word-wrap, a 2-line window) with unit tests. (5) UI: a movable caption box over the page from kit parts (derived, on derived-review.md), a Settings row (Accessibility or Appearance), and a toggle in the media hub or video strip. Linux and macOS first.

Chrome lets the user pick several spell-check languages (pref `spellcheck.dictionaries`) and downloads each `<lang>-<ver>.bdic` from redirector.gvt1.com. wubble bundles en-US only, Chromium's download host is refused (decision "Chromium's own requests", `host-resolver-rules`), and TODO "Spell check in other languages" asks for an opt-in download. To build: (1) Core (pure, tested): `wubble_core::spell` gains a table of the languages Chromium 156 supports, with their versioned file names, copied from `components/spellcheck/common/spellcheck_common.cc` `kSupportedSpellCheckerLanguages` and the version map in `chrome/browser/spellchecker/spellcheck_hunspell_dictionary.cc` (BSD, with a source comment). Add a `DictState` per language (Absent, Downloading, Ready, Failed) with a transition. `plan` is extended to multiple wanted languages, never deleting a user-wanted file. (2) Settings: a List `spell.languages` (default `["en-US"]`) and a Bool `spell.download` (default 0, `Section::Privacy`, the label naming the host). While the download setting is off, only installed languages can be picked. (3) Download through wubble's own fetch (`crates/wubble-engine/src/fetch.rs`, which goes through CEF's network stack, so pick a host that `host-resolver-rules` allows): `https://chromium.googlesource.com/chromium/deps/hunspell_dictionaries/+/refs/heads/main/<file>?format=TEXT` (base64), or a configurable mirror. Write to `<profile>/Dictionaries` atomically and check the size and a pinned SHA-256 from the table. (4) Apply the list as pref `spellcheck.dictionaries` through `View::set_preference` on each request context. On macOS, the list maps to system languages, so nothing is downloaded and the row says so.

## `pdf-print-handler`: Linux print handler: window.print() and the PDF viewer's print

Area: media-downloads. Needs an engine patch: no.

In Chrome, a page's `window.print()`, the PDF viewer's Print button and Ctrl+P on a PDF all open print preview and print what is shown. wubble's welding implements no CefPrintHandler (no print_handler in vendor/welding/src/linux_cef). On Linux, CEF needs one for printing, so a page's window.print() does nothing. Ctrl+P on a PDF is worked around in crates/wubble/src/host/print.rs `print()`: an `is_pdf` tab is downloaded instead of printed ("printing the viewer gives a blank page").

What to build: (1) welding (Linux): a WeldPrintHandler (cef::wrap_print_handler!) registered beside the find handler in linux_cef/mod.rs, marked `wubble change`. OnPrintDialog holds its callback and reports `NavigationEvent::PrintRequested { id, has_selection }`. OnPrintSettings fills the settings from the host's answer. OnPrintJob hands the host the PDF path Chromium wrote, and the job callback is completed after the host is done. OnGetPdfPaperSize returns the chosen paper. (2) Engine: a PageEvent::PrintRequested and `View::answer_print(id, Option<PrintSettings>)`. (3) Core: wubble_core::print::Sheet gains an origin `FromPage(id)`, so the existing sheet answers the page instead of calling PrintToPDF. Its Effect becomes AnswerPrint, and a job PDF goes to `lp` (or to Downloads for Save as PDF). Unit tests for the new transitions. (4) Host: remove the is_pdf download workaround. Ctrl+P on any tab calls CefBrowserHost::Print, so the PDF viewer's own document is printed through the sheet. macOS uses CEF's native print panel and needs no change; Windows stays Save as PDF.
