## `keyboard-lock-hint`: Keyboard Lock in fullscreen: system keys reach the page, hold Esc to exit

Area: web-platform-ui. Needs an engine patch: no.

In Chrome, navigator.keyboard.lock() in fullscreen gives the page keys the browser would otherwise take (Ctrl+W, Ctrl+T, Alt+Tab where the OS allows, Esc). The fullscreen bubble then says "Press and hold Esc to exit full screen" and names the site. Content's default RequestKeyboardLock accepts the lock, but wubble's shell still handles its own chords first (crates/wubble/src/input.rs routes, keys.rs), and the fullscreen hint is a generic toast (crates/wubble/src/screen.rs ScreenEffect::Hint, host/surfaces.rs "Press Esc to exit full screen").
Build: (1) Add a main-world content-script channel `kbdlock` (wubble-helper/src) that reports navigator.keyboard.lock(keys) and unlock() to the browser. (2) Add the lock to the pure fullscreen machine in crates/wubble/src/screen.rs: state Locked{keys} while the page is fullscreen and locked. Input routing then sends the shell's page-first and shell chords to the page, except the OS-reserved ones. Esc goes to the page, and a hold of 2 s (Chrome's kHoldEscapeTime is 2 s) leaves fullscreen. Unit-test the transitions. (3) Change the hint text: "Press and hold Esc to exit full screen" while locked, "<site> is now full screen" plus the Esc line, as Chrome's ExclusiveAccessBubble does, from the existing toast. (4) Ask for the KeyboardLock site permission (it already exists in site.rs) when the page locks outside a gesture, as Chrome does.

## `media-session-complete`: Media Session API and OS controls: seek, position, raise, active session

Area: media-downloads. Needs an engine patch: no.

In Chrome, MPRIS, Now Playing and SMTC show a position bar and accept seeks. The action handlers seekbackward, seekforward, seekto, skipad, togglemicrophone, togglecamera and hangup are honoured, Raise focuses the tab, and the active session is the one that most recently started playing; a paused session stays controllable. In wubble, crates/wubble/src/media_keys.rs and kit.js have only play, pause, toggle, next, previous and stop. MediaKey::of drops souvlaki's Seek, SeekBy, SetPosition, Raise and SetVolume. kit.js does not wrap `navigator.mediaSession.setPositionState` or `playbackState`. Keys::show passes `progress: None` and `duration: None`. `key_target` in host/videos.rs takes the first audible tab in map order and loses a paused session. Windows gets `hwnd: None`, so souvlaki refuses and the keys are off.

What to build: (1) kit.js: wrap setPositionState and playbackState, report them in `meta` (duration, position, rate, state), and extend `act(action, details)` with seek actions (seekTime, seekOffset) that fall back to the video element. (2) Move the active-session choice into a pure machine in a new wubble-core/src/mediasession.rs: an enum of sessions per tab, events (started playing, paused, closed, user pressed) and the chosen tab, with unit tests. (3) media_keys.rs: map Seek, SeekBy, SetPosition and Raise. Raise focuses the tab's window and tab. Pass MediaPosition and the duration, and pick the artwork size closest to 256 px. (4) Windows: pass the main window's HWND from winit. (5) Media in an iframe: the poll asks each same-origin frame's kit through `View::run_script_in`.

Check that the wording fits a package manager. Add a section to docs/release.md, and run shellcheck by hand.
